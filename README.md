# 近江八幡市.com(非公式)

近江八幡市に関する各種公式サイト等の新着情報を収集し、
RSS(rss.xml)とWebサイト(index.html / GitHub Pages)で公開する仕組み。

## 収集対象と方式

| 出典 | 方式 |
|---|---|
| 近江八幡市公式サイト(トップページ掲載) | 重要なおしらせ・お知らせ・募集情報・イベント情報のJSONを取得(日付と要約付き)。同じURLの再掲載(公開日時の更新)も検知する |
| 近江八幡市公式サイト(全体) | ハブページ監視(組織別/soshiki/ と分野別/gyosei/・/kurashi/等の一覧ページを巡回し、その配下の個別記事を検出) |
| 近江八幡経済新聞 | 公式RSS取得 |

## ファイル構成

| ファイル | 役割 | 実行順 |
|---|---|---|
| common.py | 全スクリプト共通の処理(通信・文字コード・XML補正・重複管理) | - |
| discover_hubs.py | 市サイトの部署ページ一覧(hubs.json)を作成 | 月1回 |
| fetch_city_lists.py | 市サイト トップページ掲載一覧の収集(JSON) | 1 |
| watch_hubs_and_generate_rss.py | 市サイト全体の新着収集 | 2 |
| fetch_rss_sources.py | 公式RSSを持つサイトの新着収集(RSS2.0/RSS1.0/Atom対応) | 2 |
| watch_hub_sources.py | 観光サイト・図書館の新着収集 | 3 |
| fetch_shiga_police_omihachiman.py | 警察署の活動ページの新着収集 | 4 |
| fetch_list_sources.py | RSSのない一覧ページ型サイトの新着収集 | 5 |
| fetch_tabelog_newopen.py | 食べログの新規オープン店の収集 | 6 |
| fetch_section_links.py | ページ内の指定範囲のリンクを収集(安土学区まちづくり協議会) | 7 |
| build_feed.py | 収集結果からrss.xmlを生成(日付順に整列) | 8 |
| repair_titles.py | 既存記事のタイトル・日付・要約を取り直す(手動実行時のみ) | 任意 |
| rebuild_from_known.py | 掲載枠から消えた既知記事を復元する(手動実行時のみ) | 任意 |
| reset_omi8_stories.py | 観光サイトの記事を削除し新着順一覧から取り直す(1回限り・手動実行時のみ) | 任意 |
| index.html | 公開Webサイト(rss_items.jsonを表示) | - |

収集スクリプト(1〜4)はデータファイルを更新するだけで、rss.xmlは
最後のbuild_feed.pyだけが生成する。1つのサイトで取得に失敗しても
他のサイトの収集とRSS生成は止まらない。

## 自動生成されるファイル(手で編集しない)

- hubs.json : 市サイトの巡回対象一覧(新しい一覧ページは巡回中に自動追加される)
- hub_cursor.json : ハブ巡回の続きの位置(1回あたり300件ずつ分割して巡回)
- dept_names.json : 部署URLと実際の課名の対応表(出典表示に使用)
- known_links.json : 既知記事の一覧(重複防止)
- rss_items.json : 収集した記事データ(Webサイトの表示元)
- rss.xml : RSSフィード(Feedlyに登録するのはこれ)
- feed_fingerprint.txt : 前回生成時の内容記録(無変更時のコミット抑制用)

## 再掲載の検知(市サイト トップページ一覧のみ)

市サイトは「【9月分】〜のお知らせ」のように同じURLのページを更新して再掲載する運用がある。
トップページ一覧のJSONには正確な公開日時が入っているため、URLが既知でも
公開日時が前回より新しければ「再掲載」として改めて掲載する
(RSS上は識別子に公開日を付け、リーダー側でも新着として届く)。
それ以外の収集方式は従来どおり「新しいURLの出現」のみを検知する。

## 掲載件数の考え方

収集データ(rss_items.json)は件数で切らず、日付(FEED_MIN_DATE)だけで管理する。
件数で切ると、記事数の多い市サイトが枠を占有し、他サイトの新着が
押し出されて消えてしまうため。rss.xmlに書き出す件数のみ FEED_MAX_ITEMS で制限する。

同じ記事が複数のURLで掲載されている場合(市サイトは分野別と組織別の両方に
同じ内容を載せることがある)は、タイトルと出典が同じものを1件にまとめる。

## 掲載する期間

common.py の FEED_MIN_DATE より古い記事は、公開ページ・RSSともに掲載しない
(初期設定: 2026年8月1日)。古い記事が200件の枠を埋めて新着が押し出されるのを防ぐため。
期間を変えたい場合はこの日付を書き換える。

## 記事の要約

各記事に100〜150字程度の要約を付ける。取得元は次の順。

1. 市サイトのトップページ一覧はJSONに含まれる説明文
2. ページの og:description / meta description(本文冒頭が入っていることが多い)
3. 本文の段落から生成

文の途中で切れないよう、句点で区切って整える。

## 記事の日付の扱い

原則は「元記事が示す日付」。取得日で代用すると、更新の無い古いページが
最新記事として先頭に並んでしまうため、扱いを出典ごとに分けている。

| 出典 | 日付の取得元 | 日付が無い場合 |
|---|---|---|
| 市サイト(トップページ一覧) | JSONの公開日時 | ほぼ発生しない |
| 市サイト(全体巡回) | ページの「更新日」 | **掲載しない**(中継ページ等のため) |
| RSS配信の各サイト | 配信元の日付 | 収集時刻を固定で記録 |
| 観光サイト | ページの日付情報 | 掲載を確認した日(特集等は日付表記が無いため) |
| 図書館だより | (詳細ページは本文を持たないため対象外) | 常に掲載を確認した日 |
| 一覧ページ解析の各サイト | 一覧に並ぶ日付 | 収集時刻 |
| 警察署 | 本文中の「○月○日」 | - |

図書館だよりの詳細ページは、本文(タイトル含む)をJavaScriptで後から
読み込む作りになっており、静的な取得では中身が空になる。そのため詳細ページは
開かず、一覧ページに表示されているリンクの文字列をそのまま記事タイトルとして使う。

rss.xml生成時にも、日付が空・解釈できない記事は最古扱いとし、
誤って最新記事として先頭に出ないようにしている。

日付表記の無いサイト(観光サイトの特集・モデルコース・スポット・イベント)は、
新着順に並ぶ一覧ページ(index_1_0____0___.html)を巡回し、
その並び順を保ったまま登録する(同時に見つけた記事は1秒ずつずらして順序を保持)。
これにより、以後に公開された記事が正しく上に並ぶ。

## Webサイトの記事分類

市の「目的別で探す」に倣い、各記事に最大2つのタグを自動で付与する。

- 結婚･妊娠･出産 / 子育て･教育 / ごみ･リサイクル / 住民票･証明 / 健康･医療
- 引っ越し･住まい / おくやみ / 高齢･障がい･介護 / 税金

これとは別に、イベント性のある記事には「イベント情報」を付ける(上記2つの枠には含めない)。
タグはタイトル・URL・担当課名を手がかりに自動判定するため、
分類が合わない場合は index.html の TOPIC_TAGS のキーワードを調整する。

## GitHub Pagesの利用制限と現状

| 制限 | GitHubの上限 | 本サイトの見込み | 余裕 |
|---|---|---|---|
| リポジトリ容量 | 1 GB | 10年運用で約480MB | 十分 |
| 帯域 | 月100 GB | Feedly購読1,800人相当まで | 十分 |
| ビルド回数 | 1時間10回 | 1日3回(1時間あたり最大1回) | 十分 |

- 記事データ(rss.xml / rss_items.json)は**常に最新200件までに自動で切り詰められる**ため、
  いくら新着が増えても公開ファイル自体は約150KBのまま増えません。
- 唯一増え続けるのは known_links.json(既読URLの記録)ですが、
  対象サイトの総ページ数に応じて数千件で頭打ちになり、1〜2MB程度で安定する見込みです。
- 実行のたびに build_feed.py が容量をログに出力します。合計50MBを超えると
  警告が出るので、その時点で対処を検討すれば十分間に合います。
- 変更がない場合はコミット自体をスキップするため、無駄な履歴は増えません。

## 収集対象外としたサイトと理由

- 観光サイトのグルメ・土産・宿泊・アクセス・お気に入り: 個別店舗の紹介であり、
  更新日の記載がなく新着かどうか判別できないうえ、特定の事業者の利益につながりうるため

- ラコリーナ近江八幡(taneya.jp): 公共性が低いため対象外

- 滋賀報知新聞 / 京都新聞: robots.txtによる自動アクセス拒否+有料報道コンテンツのため
  (京都新聞はGoogleニュースRSSでFeedly個人購読のみ。公開サイトへの組込はGoogle規約上不可)
